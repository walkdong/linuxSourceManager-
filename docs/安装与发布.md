# 安装与发布

面向**使用者**和**发布者**两部分。使用者只看前两节就够了。

---

## 一、给使用者：三种安装方式

### 方式 A：一行命令（推荐，任何发行版）

```sh
curl -fsSL https://raw.githubusercontent.com/source-manager/source-manager/main/scripts/install.sh | sh
```

它会做完这些事，然后告诉你"以后从应用菜单打开"：

1. 找一个 Python ≥ 3.10（找不到会提示两条出路，不会留下半成品）
2. 在 `~/.local/share/source-manager/venv` 建**独立**环境（**不动你的系统 Python**，
   也不往 `/usr` 里装任何东西）
3. 把 `srcmgr` 放到 `~/.local/bin`
4. 自动创建应用菜单图标（"源管理器"）

可选参数（用环境变量）：

| 变量 | 作用 |
|---|---|
| `SRCMGR_VERSION=v0.2.0` | 装指定版本 |
| `SRCMGR_FROM=wheel` + `SRCMGR_WHEEL=./x.whl` | 从本地 wheel 装（离线/网盘传播用） |
| `SRCMGR_PREFIX=~/.local` | 改安装前缀 |
| `SRCMGR_NO_SHORTCUT=1` | 不创建桌面图标 |

卸载（干净、无残留）：

```sh
sh -c "$(curl -fsSL https://raw.githubusercontent.com/source-manager/source-manager/main/scripts/install.sh)" --uninstall
```

> 卸载**故意保留** `~/.config/source-manager` 和 `~/.local/share/source-manager`
> （你的配置、备份、修改记录）。想彻底删掉就手动 `rm -rf` 这两个目录。

### 方式 B：单文件可执行（不需要 Python）

从 Releases 页下载 `srcmgr-linux-x86_64`，然后：

```sh
chmod +x srcmgr-linux-x86_64
./srcmgr-linux-x86_64
```

**双击下载的文件通常不行**——Linux 会先拦一下。两种办法：

- 终端里跑上面两行（最简单）
- 或在文件管理器里右键 → 属性 → 权限 → 勾选"允许作为程序执行"，然后双击

首次运行它会**把自己安装到 `~/.local/bin/srcmgr` 并创建应用菜单图标**，
之后那个下载的文件就可以删了。

还有一个 `srcmgr-cli-linux-x86_64`：纯命令行版，裸跑会打印用法（适合脚本）。

- 支持范围：**Ubuntu 22.04 / 24.04 / 26.04、Debian 12/13 及衍生版**（x86_64）。
  更老的系统装不了，因为需要 Python 3.10+。
- 网盘传播：把 `srcmgr-linux-x86_64` 和本文件一起打包成 zip 发出去即可。

### 方式 C：Flatpak（图形软件中心）

> **当前阶段说明**：Flatpak 的沙箱**看不到宿主机的 `/etc/apt`、`/etc/docker`**，所以
> Flatpak 版只能管理**用户级**下载源（npm / yarn / pnpm / pip / cargo / go / git / conda
> 以及用户级 flatpak remote）。APT、Docker 这类系统级的会显示"需要在宿主机上执行"，
> 并给出可直接复制的 `srcmgr --cli ...` 命令。
>
> 想要"软件中心一键装 + 也能改系统源"，需要额外做一个跑在宿主机上的提权助手
> （polkit 或 flatpak-spawn + sudo）。这件事必须先在真实桌面上验证过才敢发，所以
> **没有放进当前版本**。见下方"发布者"一节。

```sh
flatpak install flathub org.sourcemanager.SourceManager
```

## 二、验证与排查

**校验下载**（强烈建议：这个工具要改你的系统源，值得确认文件没被动过）

```sh
sha256sum -c SHA256SUMS --ignore-missing
```

**装完先跑这一条**，确认基本功能正常：

```sh
srcmgr --cli doctor
```

它会列出：检测到哪些生态、配置文件在哪、哪些路径需要管理员权限、source provider 是否加载。

**常见问题**

| 现象 | 原因与解决 |
|---|---|
| 终端里敲 `srcmgr` 说找不到 | `~/.local/bin` 不在 PATH。执行：`echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.profile && . ~/.profile` |
| 双击下载的文件没反应 | 见方式 B 的两条办法（chmod 或右键允许执行） |
| 提示需要密码 | 那是**管理员权限**，改系统级源（APT/Docker）时才会要，就是你的开机密码。菜单界面会弹框询问，只问一次，密码不落盘 |
| 界面里全是"未检测" | 没测过速。按"测速"，或 `srcmgr --cli health` |
| 某个源显示"打不开"但别的正常 | 那是**备用源**失效，不影响下载，界面上是黄色提示 |
| 改坏了想恢复 | 菜单里点"撤销"，或 `srcmgr --cli rollback apt`；也可以"备份"里选时间点还原 |
| 只想看看不改 | `srcmgr --cli sources`、`srcmgr --cli apt list`；一切都可加 `--dry-run` |

## 三、给发布者：怎么构建与发布

### 一次性准备

1. **改掉仓库地址**：`pyproject.toml` 的 `[project.urls]`、`scripts/install.sh` 里的
   `REPO_SLUG`、Flatpak 的 `metainfo.xml`。
2. **PyPI Trusted Publishing**（不需要存 token）：在 PyPI 项目设置里添加
   GitHub 发布者，填 `owner/repo`、workflow 名 `build.yml`、environment `pypi`。
3. GitHub 仓库建好，默认分支与 workflow 里的 `main`/`master` 对齐。

### 发布一个版本

```sh
# 1. 改版本号（两处：srcmgr/__init__.py 与 pyproject.toml），更新 PROGRESS.md
# 2. 打 tag 并推送 —— CI 会自动构建、测试、发 Release、发 PyPI
git tag v0.2.0 && git push origin v0.2.0
```

CI（`.github/workflows/build.yml`）在 tag 上会做：

| 产物 | 说明 |
|---|---|
| `*.whl` / `*.tar.gz` | PyPI 包，推送到 PyPI（OIDC，无 token） |
| `srcmgr-linux-x86_64`、`srcmgr-cli-linux-x86_64` | 单文件版，**在 ubuntu:22.04 容器里构建**（保证 glibc 兼容），并在**没有 Python 的干净容器**里冒烟测试 |
| `SHA256SUMS` | 校验和，附在 Release 里 |
| GitHub Release | 自动生成 release notes + 安装说明 |

**为什么必须在容器里构建单文件**：二进制会链接构建时的 glibc。在本机（glibc 2.43）
编出来的拿到 Ubuntu 22.04 会直接启动失败。本地想复现：

```sh
scripts/build_binary.sh            # 容器构建（需要 docker 权限）
scripts/build_binary.sh --native   # 本机快速构建，仅用于本机验证，不可分发
scripts/build_binary.sh --test     # 构建后在无 Python 容器里冒烟测试
```

> 注意：如果你的用户在 `docker` 组里才能免 sudo 用 docker；否则用 `sudo scripts/build_binary.sh`。

### Flatpak 上架

```sh
flatpak install flathub org.flatpak.Builder
flatpak run org.flatpak.Builder --user --install --force-clean \
    build/flatpak packaging/flatpak/org.sourcemanager.SourceManager.yml
```

清单里的 Python 依赖 sha256 目前是占位符（故意让它构建失败而不是悄悄装错东西），
用 `flatpak-pip-generator textual prompt_toolkit` 生成后替换，然后：

- 提 PR 到 [flathub/flathub](https://github.com/flathub/flathub)（新应用）
- 后续版本用 Flathub 的 `flathub.json` + 自动更新机器人

**如果要做"Flatpak 里也能改系统源"**（阶段 2），可行路径是先做实验验证：

1. 在 `finish-args` 里加 `--talk-name=org.freedesktop.Flatpak` 和 `--filesystem=host-os`
2. 应用内用 `flatpak-spawn --host sudo -A ...` 调用宿主机命令
3. **必须验证**：密码提示能否在沙箱内正常弹出、`SUDO_ASKPASS` 能否穿透、
   宿主机的 `sudo` 是否需要 tty

这个实验我建议在真实桌面环境做，验证结果写进 `PROGRESS.md` 再决定是否开启。

### 网盘传播

把 `srcmgr-linux-x86_64`、`SHA256SUMS`、本文件打包成 zip。加上一句使用说明：

> 下载后：右键 → 属性 → 权限 → 允许作为程序执行，然后双击。
> 或者打开终端执行 `chmod +x srcmgr-linux-x86_64 && ./srcmgr-linux-x86_64`。
